03의미 공간

Embedding: 단어에 좌표를 주기

Token 번호에는 의미가 없습니다. 그래서 각 Token을 수백~수천 개 숫자의 Vector로 바꿉니다.

비유거대한 지도. 의미가 비슷한 단어끼리 가까이 모여 있습니다.
비유의 한계실제 지도는 수천 차원이고, 축에 사람이 붙일 수 있는 이름도 없습니다.

word2vec (2013): king − man + woman을 계산하면 queen에 가장 가까운 Vector가 나옵니다.

04모델 크기

Parameter: 수십억 개의 Dial

Neural Network는 거대한 계산식이고, 곱하는 값들이 Parameter(Weight)입니다. 학습은 Dial을 맞추는 과정, 맞춘 설정값 묶음이 Model file입니다.

05학습

Loss → Backpropagation → Gradient Descent

  1. Forward Pass

    현재 Dial로 다음 Token 확률 계산

  2. Loss

    정답 확률이 낮을수록 큰 벌점 (Cross Entropy)

  3. Backpropagation

    벌점에 대한 각 Dial의 책임을 거꾸로 계산 (1986)

  4. Gradient Descent

    벌점이 줄어드는 쪽으로 Dial을 조금씩

07구조

Decoder의 규칙: 앞만 본다

Attention → Feed-forward Block을 층층이 쌓은 것이 Layer. 대화형 LLM 대부분은 Decoder-only 구조입니다.

각 Token은 자기보다 앞에 있는 Token만 볼 수 있습니다 (Masking). 다음 Token을 맞히는 모델이 정답을 미리 보면 안 되니까요.

비유Assembly line. 원재료(Embedding)가 수십 개 공정(Layer)을 거쳐 확률표라는 완제품이 됩니다.

행: 지금 Token · 열: 볼 수 있는 Token

08Post-training

Pre-training → SFT → RLHF: 학생에서 비서로

  1. Pre-training

    Internet 규모 text로 이어 쓰기를 배움. 아는 건 많지만 대화는 어색

  2. SFT (Supervised Fine-Tuning)

    사람이 쓴 "질문–모범 답변"으로 추가 학습

  3. RLHF (Reinforcement Learning from Human Feedback)

    사람 순위로 Reward Model을 만들고, 그 점수가 오르도록 강화학습

11Memory

KV Cache: 이미 읽은 건 다시 읽지 않기

13한계

Context Window: 책상의 크기

모델이 한 번에 볼 수 있는 Token의 최대 개수. Prompt, 대화 기록, 첨부 문서, 생성하는 답변까지 모두 이 안에 들어갑니다.

책상이 넓으면 자료를 많이 펼칠 수 있지만, 넘치면 밀려납니다.

14효율

MoE: 전문가 8명 중 2명만 부르기

MoE (Mixture of Experts)는 Router가 Token마다 전문가 몇 개만 골라 씁니다. 종합병원 접수처가 필요한 과 두어 곳만 안내하듯이요.

Mixtral 8x7B: 전체 470억 중 Token 하나에 쓰는 건 130억. 용량은 크게, Bandwidth 부담은 작게.
