01 · 오케스트레이션

하위 Agent가 많다고 더 똑똑해지지 않는다 판단

Agent를 늘리면 함께 늘어나는 것
컨텍스트 전달상태 동기화실행 충돌스케줄링 비용
결정론적 Workflow에 맡길 것

순서와 조건이 정해진 일

  • 입력이 같으면 결과도 같아야 하는 단계
  • 규칙으로 분기할 수 있는 처리
  • 정해진 API를 정해진 순서로 부르는 일
모델(Agent)에 맡길 것

동적 판단이 필요한 일

  • 도구 결과를 보고 다음 행동을 정해야 할 때
  • 입력이 모호하거나 예외가 많은 부분
  • 규칙으로 미리 다 적을 수 없는 불확실성
Workflow · 미리 정한 순서대로 실행되는 작업 흐름결정론적 · 같은 입력에 항상 같은 결과를 내는 성질Sub-agent · 상위 에이전트가 일부 작업을 넘겨받게 만든 하위 에이전트

03 · 메모리와 작업 상태

다시 해도 되는 일과 이미 일어난 일을 구분한다

안전하게 재시도

  • 조회 · 검색

이미 외부 부작용

두 번 하면 사고가 나는 호출

  • 이메일 · 메시지 발송
  • 비용이 청구되는 생성 API
  • 운영 데이터 변경 · 파일 업로드 완료
중복을 막는 장치

세 가지를 함께 쓴다

  • 멱등 키 · 같은 요청은 한 번만 처리
  • 작업 상태 · 무엇이 끝났는지 기록
  • 보상 메커니즘 · 이미 일어난 일을 되돌림
멱등Idempotent · 여러 번 실행해도 결과가 한 번 실행한 것과 같은 성질부작용Side effect · 시스템 밖에 남는 변화(발송, 결제, 저장 등)보상Compensation · 끝난 작업을 취소·상쇄하는 후속 처리
