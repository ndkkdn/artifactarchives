    01 · R&D 가속 평가

    METR 리포트: AI가 다음 AI를 만드는 속도를 처음으로 잰 보고서

    AI 안전·역량 평가 비영리 연구기관 METR(Model Evaluation and Threat Research)이 2026년 11월 5일, 앤트로픽 내부 데이터를 바탕으로 한 “내부 AI R&D 가속 독립 평가 보고서”를 공개했습니다.

    “AI가 차세대 AI를 직접 만든다”는 말은 그동안 주장에 가까웠습니다. 이 보고서는 그 주장을 실제 프론티어 연구소의 내부 데이터로 정량 측정한 첫 공식 독립 보고서라는 점에서 의미가 큽니다.

    1.1R&D 역량 향상 속도, 약 2배

    METR은 앤트로픽 내부 엔지니어링·벤치마크 지표(AECI 등)를 분석했습니다. 결론은 잘 정의된 과제에서 모델 개발 가속도가 2024년 3월~2025년 10월 대비 약 1.9~2.0배 빨라졌다는 것입니다. 쉽게 말해, 예전 속도로 2년 걸리던 연구 진척을 지금은 1년 만에 해낸다는 뜻입니다.

    02 · 이미지 생성

    GPT Image 2.6: 글자와 일관성, 두 난제를 함께 풀다

    OpenAI의 최신 이미지 생성 파운데이션 모델 GPT Image 2.6이 Mage, ElevenLabs 등 파트너 플랫폼과 API로 정식 공급을 시작했습니다.

    이미지 생성 모델의 오랜 약점은 두 가지였습니다. 이미지 속 글자가 깨지는 것, 그리고 여러 장을 만들면 캐릭터나 화풍이 조금씩 달라지는 것입니다. 2.6은 이 두 문제를 크게 개선했고, 애니메이션 GIF 생성과 두 가지 티어 구성을 더했습니다.

    2.1극대화된 인-이미지 텍스트 렌더링

    포스터, 브랜드 라벨, 식당 메뉴판, 다단 만화(웹툰)처럼 글자 배치가 복잡한 이미지에서도 오타 없는 타이포그래피를 만들 수 있습니다. 한국어와 영어를 섞어 쓰는 다국어 폰트 표현력도 크게 좋아졌습니다.

    2.2다중 참조(Multi-Reference) 편집

    최대 15장의 레퍼런스 이미지를 프롬프트와 함께 넣을 수 있습니다. 캐릭터 외형, 특정 오브젝트, 화풍을 일관되게 유지하면서 정밀하게 편집할 수 있다는 뜻입니다.

    2.3자체 애니메이션 GIF 생성

    텍스트 프롬프트 하나나 정지 이미지 한 장으로 2~16프레임 분량의 루프형 고화질 GIF를 바로 렌더링합니다.

    2.4Flare vs. Sunburst

    • GPT Image 2.6 Flare: 빠른 생성 속도와 비용 효율을 갖춘 기본 티어. 1K 해상도.

    03 · 가중치 직접 제어

    Weight-Space Programming: 학습 없이 가중치를 고치다

    2026년 11월 2일, MIT CSAIL 연구진(Rikiya Takehi 외)이 논문 “Sparks of Weight-Space Programming: LLMs can natively read & write neural network weights”를 발표했습니다.

    지금까지 신경망을 바꾸는 방법은 사실상 하나였습니다. 데이터를 모으고, 역전파로 오차를 계산하고, 경사 하강법으로 가중치를 조금씩 움직이는 것입니다. 이 논문은 그 과정을 건너뜁니다. LLM이 대상 신경망의 원시 가중치 텐서를 코드처럼 읽고, 원인을 분석해, 바로 고쳐 씁니다.

    3.1결함 신경망 즉각 교정: 3.5% 수정으로 0% → 100%

    강화학습(PPO) 훈련 중 국소 최적해(Local Minimum)에 빠져 주행 과제를 계속 실패하던 정책망이 있었습니다. GPT-6 Astra가 가중치 구조에서 실패 원인을 찾아냈고, 전체 가중치의 3.5%를 단 한 번 고쳤습니다. 성공률은 0%에서 100%가 되었고, 1,024회 연속 성공했습니다.

    05 · 상시 가동 에이전트

    OpenAI dots: 클라우드를 넘어 내 컴퓨터들로

    OpenAI의 차세대 퍼스널 에이전트 dots(닷츠)가 독립 클라우드 가상 환경을 넘어, 사용자가 가진 여러 대의 로컬 컴퓨터에 직접 접속해 작업을 위임·수행하는 기능을 공식 지원하기 시작했습니다.

    클라우드와 로컬의 하이브리드 협업작업 신호가 기기 사이를 오갑니다

    5.1클라우드와 로컬의 하이브리드 협업

    dots는 기본적으로 전용 클라우드 머신에서 일합니다. 그런데 웹사이트의 CAPTCHA(봇 방지)에 막히거나 사내 폐쇄망에 들어가야 할 때는, 연결된 사용자의 로컬 컴퓨터 브라우저를 백그라운드에서 호출해 우회합니다. 클라우드에서 못 하는 일을 “사람의 컴퓨터”를 빌려 해결하는 셈입니다.

    5.2멀티 디바이스 환경

    ChatGPT 데스크톱 앱으로 사무실 PC, 개인 노트북, 홈 워크스테이션 등 여러 기기를 dots에 등록할 수 있습니다. dots는 작업 유형에 따라 “A 컴퓨터에서 로컬 파일 추출”, “B 워크스테이션에서 Codex 코딩 작업과 로컬 스킬 실행”처럼 기기별로 나눠 실행합니다.

    5.3보안과 제어권 (Control & Takeover)

    내 컴퓨터를 에이전트에게 맡기는 일이라 안전장치가 중요합니다. dots에는 세 겹의 통제가 있습니다.

    ① Allow access

    로컬 접근은 기본적으로 꺼져 있습니다. 기기마다 데스크톱 앱에서 사용자가 직접 승인해야 연결됩니다.

    ⏸ Takeover
    ② 테이크오버

    작업 도중 언제든 제어권을 되찾아 사람이 직접 이어서 할 수 있습니다.

    ✕ Revoke access
    ③ 원클릭 권한 철회

    한 번의 클릭으로 기기 접근 권한을 회수해 로컬 데이터 유출 위험을 막습니다.

    5.4AI 에이전트(비서) 전쟁: dots는 혼자가 아니다

    2026년에는 dots 말고도 사람 대신 일을 처리해 주는 AI 비서가 잇달아 나왔습니다. 피클, 메타의 뮤즈, 오픈AI의 닷츠(dots), 스피어 스트리트 테크놀로지의 인스팅트가 대표적입니다. 생활 밀착형 대행, 쇼핑, 24시간 업무 수행, 대화형 업무 지시처럼 저마다 내세우는 강점이 다릅니다.

    06 · 실무 팁

    Claude 모델과 Effort, 비용 대비 품질을 맞추는 법

    Fable 같은 새 플래그십이 나오면 “제일 좋은 모델에 제일 높은 effort”로 쓰고 싶어집니다. 하지만 비용은 빠르게 커집니다. 엔지니어링·실무에서 비용과 품질을 함께 잡는 운용 가이드입니다.

    6.1사용처별 기본 모델 매핑

    일의 종류로 모델 체급을 정한다위로 갈수록 강하고 비쌉니다
    Haiku고속 · 정형
    대량 분류, 단순 텍스트 추출, 시스템 로그 파싱
    Sonnet일상 실무
    경계와 요구사항이 명확한 일상 작업
    Opus medium기본 출발점
    대다수 복합 문제, 문서 작성, 일반 아키텍처 설계
    Fable선별 투입
    극단적 추론력과 심층 에이전트 작업이 필요한 고난도 과제

    6.2출력 품질이 부족할 때, 3단계

    결과가 아쉬울 때 가장 흔한 실수는 곧바로 더 비싼 모델로 바꾸는 것입니다. 순서를 지키면 비용을 아끼면서 원인을 정확히 찾을 수 있습니다.

    1
    검증 장치를 먼저 붙인다

    모델이 테스트 코드, 빌드 스크립트, 단위 검증을 직접 돌려 결과를 스스로 확인할 수 있는 피드백 루프를 만듭니다.

    생성→ 테스트→ 실패 로그→ 수정✓ 통과
    2
    Effort를 한 단계만 올린다

    검증 장치가 있는데도 결과가 아쉬우면 effort를 한 단계 올려 다시 추론하게 합니다.

    low high
    3
    그래도 안 되면 상위 모델로

    그래도 실패하면 상위 모델로 바꿉니다. 단, 모델을 바꿀 때는 effort를 다시 low/medium으로 낮춰서 시작합니다. 체급과 effort를 동시에 올리면 비용이 이중으로 늘어납니다.

    6.3Effort를 무조건 올리면 안 되는 이유

    • high 이상에서는 effort 한 단계를 올리는 추가 비용이 모델 체급을 한 단계 올리는 비용만큼 커질 수 있습니다.
    • Effort를 높여도 사전 학습에서 익히지 못한 배경 지식이나 본래 없는 능력이 새로 생기지는 않습니다. 더 오래 생각한다고 모르는 걸 알게 되지는 않습니다.

    6.4비용 절감을 위한 Low-First 전략

    모든 작업을 처음부터 high로 돌리지 않습니다. 먼저 low로 전부 돌리고, 검증에 실패한 작업만 골라 high로 다시 실행합니다. 전체 비용을 크게 낮추면서 최종 성공률은 높이는, 가장 이상적인 파이프라인입니다. 아래에서 실패율과 비용 비율을 바꿔 보며 직접 비교해 보세요.

    요약 및 결론

    다섯 가지 소식은 따로 보면 개별 뉴스지만, 모아 보면 한 방향을 가리킵니다. AI가 더 빨리 만들어지고, 직접 고쳐지고, 더 넓은 환경을 다루게 되고 있습니다. 그만큼 쓰는 쪽에서는 비용을 다루는 기술이 중요해집니다.

    01
    R&D 자동화 가속

    METR 보고서가 보여 주듯, AI가 차세대 AI를 개발하는 속도가 약 2배 빨라졌습니다.

     02
    가중치 직접 수정 시대

    MIT의 Weight-Space Programming은 역전파 없이 AI가 신경망 가중치를 직접 프로그래밍하는 길을 열었습니다.

     03
    프론티어 경쟁과 특화

    Gemini Carbon, GPT-6.2 Astra, Fable·Mythos 5.2의 경쟁은 텍스트 성능을 넘어 고난도 에이전트와 사이버·과학 특화 모델로 세분화되고 있습니다.

     04
    에이전트의 로컬 제어 확장

    dots의 멀티 로컬 컴퓨터 제어와 GPT Image 2.6의 복합 레퍼런스 편집은 AI가 사용자의 실제 작업 환경 전반을 대행하는 흐름을 보여 줍니다.

     05
    비용 효율적 모델 운용

    모델 체급, 인퍼런스 노력도(Effort), 자체 검증 루프를 3단으로 조정하면 최고 사양 모델을 남용하지 않고도 최대 효율을 낼 수 있습니다.

    이 페이지는 「최신 AI 핵심 동향 심층 분석 보고서」의 내용을 웹 읽기용으로 다시 구성한 것입니다. 수치와 사실 관계는 보고서를 따랐고, 도해와 데모는 이해를 돕기 위해 새로 만들었습니다. “예시”, “가정값”이라고 적힌 그림은 보고서에 없는 내용입니다. 같은 내용을 한 장씩 넘기며 보려면 슬라이드형(20장)을 열어 보세요.
